## Главное

1. **AA-006 / S1. Ошибка расчёта цен:** пропанол с явной ценой 1 200 ₽/кг превращается в 57,14 ₽/кг, как будто это баллон пропана. Для пропана ошибку независимо воспроизвели и через реальную функцию извлечения предложения с подменой ИИ и DaData в памяти.
2. **AA-007 / S1. В мониторинге цен оплачиваемый радиус не проверяется:** город используется в поисковом запросе, километраж — в комментарии отчёта, но расстояние до каждого поставщика не рассчитывается.
3. **AA-009 и AA-010 / S1. География может быть недостоверной:** один только регион превращается в «0 км»; сервер принимает радиус без города и всё равно добавляет надбавку.
4. **AA-012 / S2. API — только часть возможностей кабинета:** три операции и баланс, без мониторинга цен, километража, загрузки файлов и протокола подтверждения исходных позиций.
5. **AA-013 / S1. Автономный тестовый ключ по умолчанию получает 999 999 вызовов каждого модуля без денежного баланса клиента.** Это риск контроля расходов при выдаче ключей администратором, а не доступ постороннего без авторизации.

| Функция / канал | Что реализовано | Ограничение |
|---|---|---|
| Кабинет: поиск поставщиков, сбалансированный и попозиционный | Город и радиус передаются; расстояние отмечается, близкие компании получают приоритет | Дальние и неизвестные адреса допускаются; это не строгий фильтр |
| Кабинет: анализ + поиск | Общий механизм поиска поставщиков | Те же ограничения |

## Подтверждённые находки и план исправления

### AA-006. Ошибочный газовый пересчёт — S1 · дефект

`backend/app/price_monitoring/extractor.py:542-576`: подстрока названия и порог цены могут включить деление на 21, 6,3 или 24 без доказанной баллонной фасовки, даже когда единица сайта уже совпадает с единицей клиента. `extract_supplier_quote:1028` вызывает этот пересчёт после извлечения фактов.

| Синтетический вход | Единица сайта / клиента | Было | Получилось |
|---|---|---:|---:|
| Пропан газ | кг / кг | 500 ₽ | 23,81 ₽/кг |
| Пропанол-2, чда | кг / кг | 1 200 ₽ | 57,14 ₽/кг |
| Кислород газообразный | м3 / м3 | 1 260 ₽ | 200 ₽/м3 |
| Азотная кислота | м3 / м3 | 12 000 ₽ | 1 904,76 ₽/м3 |

**Исправление:** сохранять подтверждённую цену в совпадающей единице; пересчитывать только из доказанной фасовки/массы/объёма конкретного предложения. Идентичность вещества определять по смыслу и источнику, не по фрагменту названия. Регрессии: эти четыре отрицательных примера и действительные баллоны. Не утверждается, что конкретная прошлая задача клиента была затронута: её первичные источники отдельно не пересматривались.

### AA-007. Надбавка за радиус в мониторинге без исполнения радиуса — S1 · дефект

`jobs.py:1795-1816` передаёт радиус пайплайну; `price_monitoring/pipeline.py:945-960` передаёт каждой позиции только город. Радиус появляется при генерации Excel (`:995-1003`), но не при проверке предложения. `billing.py:735-751` начисляет надбавку.

**Исправление:** единая проверка географии каждого предложения, расстояние и источник адреса в результате, отдельный статус неизвестного адреса. Доплату связывать с реально исполненной и явно описанной геооперацией. Приёмка: одинаковые near/far/unknown предложения обрабатываются по одной политике в поставщиках и мониторинге, итоговая стоимость объяснима.

### AA-008. Название «поиск в радиусе» и фактический локальный приоритет расходятся — S2 · контракт/UX

`supplier_search.py:3961-3989,2174-2183` сортирует и аннотирует, но не исключает outside/unknown; `report_builder.py:679-684` явно допускает добор по РФ. Поэтому отсутствие строгого исключения само по себе не названо новым нарушением существующего алгоритма.

**Исправление:** явно показать два поведения: строгий радиус и разрешённый клиентом добор вне радиуса; либо последовательно назвать текущий режим локальным приоритетом. Выбор должен быть виден до оплаты. Нельзя просто удалить дальних поставщиков без решения о доборе.

### AA-009. Регион без адреса может стать «0 км, внутри радиуса» — S1 · дефект данных

`supplier_locations.py:505-539` извлекает/подставляет столицу региона, в том числе нулевую дистанцию при совпадении региона. Локально воспроизведено: только `region=Московская область`, доставка Москва, радиус 10 → `supplier_city=москва`, distance 0, within true.

**Исправление:** неизвестный адрес остаётся unknown; регион и подтверждённый пункт отгрузки — разные поля. Приёмка: запись без города/адреса не получает статус «в радиусе» по региону.

### AA-010. Неполная валидация города/радиуса и скрытый перенос настроек — S1 · дефект; UI-часть S2

`main.py:4538-4545` не проверяет пару город+радиус и диапазон; `jobs.py:192-193` молча заменяет 0/отрицательные значения на None. Стоимость определяется положительным радиусом, даже без города. Неизвестный город не отклоняется до начала работы. Изолированная БД: базовая цена 10 000 коп., радиус 300 без города → 13 000 коп. при надбавке 30%.

В кабинете `selectScenario:1643` сохраняет геосостояние, `submitJob:2100` отправляет его независимо от режима. Браузерный стенд: exact/procurement получили скрытые city+300. У этих двух режимов геонаценки нет и география игнорируется; подтверждённого лишнего списания для них нет. Пустое поле радиуса проходит HTML-валидацию и отправляется как 0.

**Исправление:** единая серверная валидация поддерживаемого режима, пары полей, диапазона и разрешимой точки доставки до резерва; явная ошибка вместо молчаливого отключения. Интерфейс отправляет поля только при видимом/доступном режиме, радиус обязателен при включении. Неизвестная география не должна маскироваться под исполненную геоуслугу.

### AA-011. «Найти ещё» теряет географию — S1 · дефект продолжения

`main.py:5051-5066` создаёт дополнительную задачу без города/радиуса родителя, в отличие от admin rerun (`:3197-3199`). Переход из подбора к поставщикам (`:5347-5359`) тоже их не передаёт, но у самого подбора георежим не предлагается: здесь важнее дать явную настройку нового поиска.

**Исправление:** наследовать и показывать геополитики в дополнительном поиске; новую географию при переходе из подбора запрашивать/задавать явно. Приёмка: город, радиус, добор и цена продолжения совпадают с видимыми настройками.

### AA-012. Внешний API не равен кабинету — S2 · пробел возможностей

`McpSupplierSearchRequest:602-668` имеет только city. Синтетический `geo_radius_km=150` исчезает из `model_dump()`. Нет API-мониторинга, файлового ввода, выбора исходных строк, асинхронных статусов и подтверждения выбора. Эти отсутствующие возможности — пробел продукта, а не доказательство неисправности трёх заявленных операций.

**Исправление:** опубликованная таблица поддерживаемых функций; затем единый протокол запуска/выбора/статуса/результата и геополитики для внешнего API. Не игнорировать неподдерживаемые смысловые параметры молча. В Telegram отдельного радиуса также нет.

### AA-013. Почти неограниченный автономный ключ по умолчанию — S1 · риск расходов

`frontend/src/McpApiView.tsx:145-160,763-770`: без привязки к клиенту, по 999999 квот трёх модулей, без ввода квоты в форме создания. `mcp_api.py:442-450,487-495`: реальная работа с квотой, без списания клиентского баланса. Админские права для создания требуются.

Дополнительно воспроизведён обход малой квоты: при лимите 1 два старта до завершения обоих проходят, затем счётчик становится 2. Проверка квоты в `mcp_api.py:442-450` не резервирует единицу, а завершение `:487-495` увеличивает счётчик позднее. Это подтверждено независимо двумя проходами на изолированной БД.

**Исправление:** атомарно резервировать квоту до работы и завершать/освобождать её ровно один раз; производственный ключ привязан к клиенту; автономный режим явно ограничен квотой, сроком и бюджетом. Тестовый режим не должен обозначать бесплатную для сервера работу. Приёмка: стандартное создание ключа не даёт неявный большой бюджет.

### AA-014. Повтор оплачиваемого API-вызова после таймаута не защищён — S2 · технический риск

У синхронных POST нет сохранённого `Idempotency-Key`; каждый повтор может создать новую задачу/резерв и оплатиться отдельно. Python MCP ждёт 300 с; это не устраняет неопределённость после разрыва соединения. Наблюдавшихся двойных списаний эта ревизия не устанавливает.

**Исправление:** сохранённый ключ идемпотентности с отпечатком запроса, статусом и возвратом того же результата; противоречащий повтор — 409. Долгие операции — задание и опрос статуса.

### AA-015. Отчёт API доступен по бессрочной непрозрачной ссылке — S2 · риск доступа

`mcp_api.py:1123-1129,1315-1333`: случайное имя файла, без проверки API-ключа/владельца и без срока ссылки. Это не предсказуемый URL и не доказательство утечки. Но тот, кто получил ссылку, может скачать документ, пока файл хранится.

**Исправление:** выбор явного контракта: доступ владельца по ключу либо ограниченная по времени подписанная ссылка. Приёмка: чужой ключ не получает документ; истёкшая ссылка не работает.

### AA-016. Товарные смысловые условия нарушают буквальную универсальность правила 14 — S2 · дефект группировки и риск охвата

Определение в `docs/PROJECT_STATUS.md:616-620`: семантический анализ без бесконечных товарных if/else. В `position_selection.py:40-52` только панели/саморезы/уголки получают отдельные группы. Иные товары попадают в общую группу; строки и цена от этого не теряются. `supplier_search.py:6245-6315` содержит особые товарные маркеры, включая запрет «швеллер» для сильного поискового якоря. Это не доказательство полного исключения швеллера из всей выдачи.

В старом пути `exact_product/deep.py:131-137,3000-3010` классификация предпочитает промышленное оборудование и исключает расходники; если фильтр вернул пустой набор, исходный набор сохраняется. Текущий путь явно выбранных строк в `pipeline.py:145-200` обходит эту классификацию, поэтому потеря выбранных саморезов в новом кабинете не утверждается. API без selected_positions может проходить старый путь.

**Исправление:** категории из исходного документа/семантического анализа и нейтральный fallback; проверка одинаковой сохранности строк для разных товаров. Не удалять защитные фильтры вслепую. Структурные заголовки таблиц, идентификаторы, математические единицы, лимит тарифа и проверки доступа сами по себе не являются товарным хардкодом.

### AA-017. Хранение открытых ключей, изменяющий GET и ограничения повторов — S2 · технический риск

`main.py:1021-1067` сохраняет открытый ключ и повторно отдаёт его владельцу при листинге. `mcp_api.py:1443-1491` GET master создаёт/восстанавливает ключ при отсутствии. Это защищённые маршруты, но доступ к сессии даёт и долговременные секреты. Ограничитель запросов хранится в памяти процесса и не сообщает Retry-After.

**Исправление:** явный контракт хранения ключей, показ нового секрета один раз/ротация, отдельная аудируемая операция создания master. Retry-After и согласованный лимит между процессами при масштабировании. Существующую выдачу ключей менять с учётом совместимости интеграций.

### AA-018. Позднее завершение API отменяет отмену клиента — S2 · дефект состояния

`mcp_api.py:453-495` завершает задачу без условного перехода состояния. Два независимых изолированных прохода: start → release/cancelled → late finalize дают `completed` и spent=1. Баланс остаётся прежним, резерв 0, в журнале только reserve/release: повторное списание в этом сценарии **не произошло**. Отмена не останавливает выполнение синхронного API-вызова, а итоговый статус и счётчик не отражают намерение клиента.

**Исправление:** общий протокол условного завершения/отмены с проверкой актуального состояния перед публикацией и изменением счётчика. Приёмка: отменённая задача не возвращается в completed, usage/резерв/стоимость согласованы. Воспроизведение: `raw/probe_api_races.py`, `raw/api-races.json`.

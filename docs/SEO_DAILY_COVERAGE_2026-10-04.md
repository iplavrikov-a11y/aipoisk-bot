# TenderLex: свежие дни в SEO-аналитике

4 октября 2026, проверка примерно в 08:30–08:45 UTC. Раздел admin.tenderlex.ru.

## Итог

Админка показывает весь календарь последних 30 дней до текущей даты МСК, отдельно для Яндекса и Google. Яндекс предоставил показы и клики по 4 октября, Google — предварительные данные по 3 октября. Дата без строки и отдельно отсутствующая позиция остаются неизвестными. Ручных согласований, кнопок отклонения и SEO-отправок в панели нет; решения выполняются через агента.

## Подтверждённые причины и исправления

| Причина                                                                                        | Исправление                                                                                                                            |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Дневной Яндекс строился из выборки фраз, закончившейся 1 октября                               | `search-queries/all/history`: все запросы ресурса, отдельные массивы показов/кликов/позиций, 30 дней до текущей даты                   |
| Google запрашивался только в режиме завершённых данных                                         | Отдельный дневной `dataState=all`, маркер `firstIncompleteDate`, явная отметка предварительных строк                                   |
| Фиксированная задержка Google ошибочно принималась за подтверждение завершённого периода       | Сводка привязана к последней дате, реально полученной в режиме `final`: сейчас 29 сентября. Дневной свежий ряд имеет отдельный период  |
| Интерфейс обрезал массив до 14 вернувшихся строк                                               | По 30 календарных строк у каждого источника, включая недоступные дни и дату, ещё не начавшуюся в PT                                    |
| Фоновый монитор сохранял отдельный отчёт в `/var/lib/tenderlex-seo-monitor`, не снимок админки | Отдельные `tenderlex-seo-admin.service/timer`, независимый часовой сбор в основной снимок. Старый монитор сохранён                     |
| Кэш снимка держался до 6 часов                                                                 | Срок 1 час, проверка времени сбора и версии дневного контракта; блокировки потока и файла между API и коллектором                      |
| Сбой одной части Яндекса скрывал пригодные данные других частей                                | Независимые статусы сводки, запросов и дневного ряда; история сохраняет предыдущую запись отсутствующего источника с её временем сбора |
| Общие дневные выводы смешивали разные источники                                                | Метрики разделены, нет ложных общих позиций и признаков роста ранжирования по смене выборки                                            |

Предыдущая проверка интерфейса проверяла имеющиеся строки и ошибки вёрстки, но пропустила полноту календаря и доступность свежих дат в источниках. Это существенный пробел той проверки. Теперь есть регрессионные проверки получения свежих дней, границы часовых поясов, пропусков, нулей, сроков кэша и повреждённых ключей даты.

## Проверка

- Полный backend: 799 тестов и 54 подтеста прошли. После дополнительной защиты от пустых ключей даты — 44 целевых теста; регрессия сначала воспроизведена, затем устранена. Production TypeScript/Vite build успешен.
- 11 браузерных сценариев на синтетических данных: desktop/mobile, недоступный источник, HTTP-сбой, повреждённый ответ, восстановление, устаревший снимок, сессия, вход, повторное открытие, сеть. Во всех доступных случаях проверены 60 календарных строк и свежая граница даты.
- Авторизованный Chrome: 13 проверок, все 9 разделов, desktop 1440 px/mobile 390 px, вход без перезагрузки. Нет ошибок JavaScript, ошибок API и бизнес-запросов на запись; SEO-кнопок нет.
- Штатный backend deploy выполнен с ограждением активных задач и проверкой сервисов. Публичный Next.js-сайт не пересобирался и не перезапускался: PID 2627901 сохранён.
- Часовой таймер включён; первый запуск сервиса завершился `Result=success`, `ExecMainStatus=0`. Он читает только аналитику, не запускает клиентские задачи, отправки в Telegram и переобход. Длительное наблюдение за несколькими часовыми циклами пока не проведено.
- Четыре публичных ответа совпали с новой контрольной точкой при заключительной проверке. Старый снимок главной страницы от 3 октября имел иной SHA-256, тогда как robots, sitemap и публичный API совпали. У сайта настроена регенерация каждые 300 секунд; это возможное объяснение различия, точная причина исторического изменения байтов не установлена. Данное исправление не меняло исходники публичного сайта или его процесс.
- [Машинные результаты](seo-daily-coverage-2026-10-04/live-checks.json). Ключи, сессии, реальные пароли и клиентские данные не публиковались.

Оценка функциональности раздела: **9/10**. Исправленная полнота дат и работа источников подтверждены; другие браузеры и длительная эксплуатация новых фоновых циклов ещё не проверены. Оценка не относится к позициям в поиске. Следующие действия агента — наблюдение за фоновой свежестью и сравнение равных завершённых периодов; ручных действий владельца в админке не требуется.

## Эксплуатация агентом

Установка таймера: `bash scripts/install_seo_admin_timer.sh`; проверка: `systemctl list-timers tenderlex-seo-admin.timer` и `journalctl -u tenderlex-seo-admin.service`. Эти операции выполнены агентом; пользователь не должен запускать их вручную. Прямой коллектор: `PYTHONPATH=backend backend/.venv/bin/python scripts/refresh_seo_snapshot.py`. Он использует тот же снимок и блокировку, что API, и уважает часовой срок данных.

## Официальные источники

[Яндекс: общая история запросов](https://yandex.ru/dev/webmaster/doc/ru/reference/host-search-queries-history-all) возвращает независимые массивы показов, кликов и средней позиции.

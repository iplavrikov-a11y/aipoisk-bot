Дополнительная проверка выявила ещё один путь повторного запуска: обычный worker мог забрать устаревшую синхронную API-задачу. Прямые `api:`-задачи исключены из этого механизма; очередные `web:api:` обрабатываются штатно. Если прямой вызов не обновлялся более 60 минут, задача завершается ошибкой с возвратом резерва, без повторного рыночного поиска. Это ограничение описано явно: настоящий прямой вызов длительностью свыше часа тоже может завершиться таким образом; для длительной работы предназначена очередь.

## Сохранённые продуктовые правила

- Подбор товара и аналогов: только Word, фиксированный тариф задачи, до пяти явно выбранных строк; без скрытого выбора и списания за каждую строку.
- Мониторинг: оплачиваются найденные выбранные позиции по действующим правилам системы.
- Поиск поставщиков: сбалансированная и попозиционная стратегии сохраняются. В модальном окне попозиционного запуска больше нет обещания «1 поиск».
- География — приблизительное расстояние между известными городами, а не маршрут грузовика или гарантия склада. Неизвестные города/адреса не заменяются догадкой; корректность города доставки проверяется локальным справочником до платного запуска.
- Действующие хэши API-ключей сохранены; ротация не запускалась. Права мониторинга у существующих ключей не включаются скрытно.
- Все клиентские обращения выполняют свежую обработку. Идемпотентность не возвращает сохранённый рыночный ответ новой задаче.

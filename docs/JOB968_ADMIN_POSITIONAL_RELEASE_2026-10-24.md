# XLSX №968 и согласованность попозиционного администрирования

Дата: 24 октября 2026. Этот отчёт дополняет [выпуск API, правила 14 и географии](API_RULE14_GEO_RELEASE_2026-10-23.md) и [руководство API](API_CLIENT_GUIDE.md).

## Причина ошибки №968

В исходном Excel форматирование растянуло диапазон листа до 16 384 столбцов. Парсер добавлял разделители для пустого хвоста каждой строки: 48 непустых значений превращались в 296 770 символов. Модель получала только начало текста, существенная часть документа оказывалась за пределами контекста; извлечение вернуло ноль товаров.

Парсер теперь удаляет пустые хвостовые ячейки перед формированием текста. Внутренние пропуски, порядок, реальные значения даже в последнем столбце сохраняются; книга закрывается после чтения. На сохранённом входе №968 получилось 2 002 символа, все 48 значений находятся в передаваемом модели начале текста. Проверка не вызывала модель или поиск. Историческая задача и её расчёты не переписаны, автоматического перезапуска нет. Успешное извлечение текста не подменяет проверку нового рыночного результата.

## Что видит и делает администратор

| Состояние | Отображение и действие | Расчёт и результат |
|---|---|---|
| Клиент закрыл окно, не подтвердив выбор | Задача остаётся ожидающей; распознанный и выбранный объём показаны отдельно от найденных поставщиков | Закрытие окна само по себе не подтверждает выбор и не создаёт списание |
| Ожидание менее 24 часов | Администратор видит исходные строки и может явно подтвердить состав; для поставщиков — также стратегию | Подтверждение исходной клиентской задачи использует её обычный тариф и резерв; интерфейс это объясняет |
| Выбор не подтверждён 24 часа | Отдельный статус истечения срока для поставщиков, подбора и мониторинга | Незавершённый резерв возвращается, списания нет; готовые старые частичные отчёты без резерва не переводятся в этот статус |
| Требуется поиск после истечения срока | Только явный новый состав строк и актуальная версия списка создают дочернюю экспертную задачу | Истёкший оригинал не возобновляется, клиент не оплачивает внутренний экспертный поиск |
| Эксперт повторяет подтверждённую задачу | По умолчанию сохранены исходный выбор, стратегия и город/радиус; другой состав задаётся явно | Новый поиск выполняется заново; старые кандидаты и рыночные результаты не используются |
| Дочерняя задача уже ожидает выбора | Видны её состояние, выбор и история, повторный слепой запуск заблокирован | Подтверждается конкретная дочерняя задача |
| Эксперт дополняет отчёт | Загружаются готовые файлы и комментарий, отдельно от запуска поиска | Отправка уведомления в Telegram — только по явному выбору администратора; проверка не отправляла сообщений |

Ограничение подбора остаётся до пяти явно выбранных исходных товаров, отчёт — Word. Мониторинг поддерживает больший выбранный состав. Для поставщиков стратегии `balanced` и `per_item` обе соблюдают выбранный набор исходных строк. Категории снабжения и товары не подменяются друг другом при подтверждении.

## Защита выбора и бесплатного экспертного повтора

- Версия списка и ID проверяются до изменения состояния, резервирования и постановки в очередь. Устаревший, пустой, частичный или неизвестный явный выбор отклоняется. Ошибка не запускает автоматический повтор; интерфейс сохраняет выбор для проверки человеком.
- Новая экспертная задача получает собственные версию/ID с сохранением номеров исходных строк. Исходный документ и родительская задача не изменяются. Администратор видит состав, географию и отсутствие списания до подтверждения экспертного повтора.
- Для старых подтверждённых задач отсутствие сохранённого списка означает весь исходный состав; явно пустой список не превращается в «все». Неподтверждённая задача не получает автоматический выбор.
- Внутренний экспертный подбор и мониторинг завершаются без списания клиентских денег, независимо от доступного баланса. Публикация результата и освобождение возможного старого резерва выполняются одной транзакцией; отмена, выигравшая гонку, препятствует публикации. Отчёт внутреннего мониторинга не показывает фиктивную стоимость услуги.
- После действия админка обновляет одну родительскую задачу, сохраняя фильтры и открытые разделы; периодическое обновление и несохранённые формы остаются под регрессионным контролем.

## API и MCP

Очередной API передаёт `revision` при выборе стратегии, поддерживает `supplier_search` и `analysis_and_suppliers`. Автономный MCP-скрипт передаёт ту же версию списка. Две копии скрипта и руководства совпадают. Клиенту рекомендуется получать актуальную `multi_item_details.revision` и подтверждать её вместе с ID; сервер сохраняет совместимость запросов стратегии без этого дополнительного поля.
